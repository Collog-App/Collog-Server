## 1. `COUGH_EVENTS` 재현율이 사실상 0 (최우선)

> **2026-08-13 갱신**: 아래 진단을 공개 도메인 라벨 음원으로 재현했고, 1번 항목(값 노출 중단)은
> 완료했다. `Settings.cough_detector_validated = False`가 기본값이며 `COUGH_EVENTS`는
> `UNMEASURABLE(DETECTOR_NOT_VALIDATED)`로 나간다. 항별 실측 분해는 아래 "실측 재현"을 본다.
> 2~4번(라벨 수집, harness, classifier 교체)은 그대로 남아 있다.

### 증상

실기기 통화에서 기침을 두 번 했는데 `COUGH_EVENTS = 0.0`, 상태는 `OK`로 저장됐다.

### 근거

TTS 음원에 광대역 폭발음을 합성해 넣고 `_cough_candidates`를 직접 호출했다.

| 삽입 신호 | 탐지 |
|---|---|
| 없음 | 0회 |
| +6 dB / 0.3초 × 2 | 0회 |
| +20 dB / 0.3초 × 2 | 0회 |
| +30 dB / 0.3초 × 2 | 0회 |
| +40 dB / 0.3초 × 2 | 0회 |

+30 dB 폭발음이 들어간 프레임의 점수를 분해하면 다음과 같다. 임계값은 0.65다.

| 항목 | 점수 | 가중치 | 기여 |
|---|---|---|---|
| high (1 kHz 이상 비율 0.703) | 1.00 | 0.25 | 0.250 |
| zcr (0.229) | 0.90 | 0.20 | 0.181 |
| energy | 0.22 | 0.40 | 0.089 |
| crest (2.20) | 0.00 | 0.15 | 0.000 |
| **합계** | | | **0.520** |

### 원인

- **분석 창이 0.96초로 기침 길이(약 0.3초)의 세 배다.** 짧은 폭발이 긴 프레임에 평균되어
  에너지가 희석된다. `energy_score = (dB - median - 6) / 18`은 median 대비 24 dB 초과를
  요구하는데, 희석 때문에 10 dB 남짓밖에 오르지 않는다.
- **crest를 같은 프레임 안에서 `max / rms`로 계산한다.** 기침이 들어오면 분자와 분모가 함께
  커져 비율이 거의 변하지 않는다. 기준이 `(crest - 3) / 8`이라 3 미만은 전부 0이 되고,
  통화 중 기침에서는 원리적으로 이 항이 반응할 수 없다.
- 두 항의 가중치 합이 0.55다. 나머지 0.45를 만점 받아도 0.65에 도달하지 못한다. 즉 현재
  임계값은 **도달 불가능한 값**이다.

### 실측 재현 (2026-08-13)

Wikimedia Commons 공개 도메인 음원 8개(기침 4, hard negative 4)를 16 kHz mono로 변환해
`_cough_candidates`를 직접 호출했다. 가장 높은 점수를 받은 프레임의 항별 분해다.

| 파일 | energy(0.40) | high(0.25) | zcr(0.20) | crest(0.15) | 합계 |
|---|---:|---:|---:|---:|---:|
| Man_coughing (기침) | 0.000 | 0.000 | 0.033 | 0.114 | 0.147 |
| Cough_1 (기침) | 0.000 | 0.214 | 0.200 | 0.150 | 0.564 |
| Cough_2 (기침) | 0.200 | 0.148 | 0.130 | 0.132 | **0.609** |
| Woman_coughing_three_times (기침) | 0.000 | 0.207 | 0.100 | 0.132 | 0.440 |
| Laughter (웃음) | 0.000 | **0.250** | **0.200** | 0.123 | 0.573 |

threshold 0.65에서 8개 전부 0회다. 0.40으로 낮추면 웃음 7회 > Cough_1 5회 > 재채기·헛기침
2회 순으로, 웃음이 모든 기침 파일보다 높다.

위 "원인"의 crest 분석은 **일부 정정이 필요하다.** 단독 녹음에서 crest는 9~18로 문턱 3을 크게
넘어 정상 동작한다. `crest = 2.20`은 TTS 발화에 폭발음을 합성한 조건의 값이었다. 정확히는
"발화가 프레임을 채우는 통화 조건에서만 붕괴한다"이며, 우리 용도가 통화 조건이라 결론은
같다.

실제로 죽은 항은 **energy 하나**다. 기준선을 클립 자신의 median으로 잡기 때문에, 기침이 잦은
녹음에서는 median 프레임 자체가 기침이 되어 가장 큰 기침도 0점을 받는다. 값이 기침의 성질이
아니라 "녹음에 기침이 얼마나 많은가"에 따라 변하는 자기참조 구조다.

더 근본적인 문제는 **살아 있는 두 항(high, zcr)이 웃음에 만점을 준다**는 것이다. 네 축은
"크고 넓은 대역의 잡음성 순간"만 기술할 수 있고, 그것은 웃음·재채기·문 닫힘·한국어 파열음에
똑같이 해당한다. 무슨 소리인지 담을 표현력이 없으므로 상수 튜닝으로는 해결되지 않는다.

## 3. `PAUSE_RATIO`가 구조적으로 0

### 증상

TTS 음원과 실기기 통화 모두에서 항상 `0.0`이 나온다.

### 원인

`_pause_ratio`는 **한 segment 안의 단어 사이 간격**만 센다. 그런데 Deepgram은 쉬는 지점에서
segment를 나눈다. 실제 휴지는 대부분 segment 경계로 이동해 계산에서 빠진다.

### 해야 할 일

segment 경계를 가로지르는 간격을 포함할지 결정한다. 이는 지표 정의 변경이므로 기준선
비교 대상이 바뀐다. 팀 결정이 필요하고, 바꾸면 analyzer version을 올린다.

### 변경 사항 (2026-11-16, 휴지 담당 결정)

1·2·4·5는 `collog-acoustic-v6`에 반영했다(정의는 `acoustic-design.md` 4-2). 3·6은 남아 있다.
v5 이전에 저장된 `PAUSE_RATIO`는 모두 0이라 v6 값과 기준선을 섞으면 안 된다. 기준선 계산은
analyzer version으로 거르지 않으므로, 마이그레이션 `0018_pause_ratio_v6`이 옛 값을
`UNMEASURABLE(DEFINITION_CHANGED)`로 바꾸고 `PAUSE_RATIO` 기준선을 지운다.

1. **휴지를 세 종류로 나눈다.** 지금은 첫 번째만 세고 있어 값이 항상 0이다.
   - 발화 내부 휴지: 같은 Deepgram segment 안의 단어 사이 간격
   - 부모 연속 발화 사이 휴지: 부모 segment끼리의 간격 중 **그 사이에 자녀 발화가 없는 것**
   - 턴 전환 지연: 자녀 발화가 끝난 뒤 부모가 응답하기까지의 시간
2. **`PAUSE_RATIO`에는 앞의 두 종류를 넣는다.** 자녀 발화가 끼지 않고 `pause_max_gap_ms` 이하
   간격으로 이어진 부모 segment들을 하나의 묶음으로 보고, 묶음 안의 모든 단어 간격 중
   [`pause_min_gap_ms`, `pause_max_gap_ms`]인 것을 더한다. 분모는 묶음별 첫 단어 시작부터
   마지막 단어 끝까지의 시간을 합한 값이다.
3. **턴 전환 지연은 `PAUSE_RATIO`에 섞지 않는다.** 필요하면 별도 지표로 만든다.
   이때 직전 자녀 발화가 단서였는지(질문인지, 말을 이어준 것인지)도 함께 기록한다.
4. **분석 입력에 자녀 segment를 넘긴다.** 현재 `AcousticAnalysisInput`에는 `parent_segments`만
   들어간다(`pipeline.py`). 자녀 트랙이 없는 통화는 묶음 사이에 자녀 발화가 있었는지 알 수
   없으므로 `UNMEASURABLE(NO_CHILD_TRACK)`로 둔다.
5. **문서와 코드를 맞춘다.** `acoustic-design.md` 4-2는 단위가 0..1이고 유효 utterance가
   최소 3개라고 적혀 있었으나 코드는 `%`에 1개였다. 저장 단위 `%`, 단어 2개 이상인 run 1개로 맞췄다.
6. **맥락을 함께 저장하고 기준선을 나눈다.** 질문 유형과 낱말(음절) 수를 휴지 값과 함께 남기고,
   기준선은 질문 유형별로 계산한다.

근거: 김시내·신상은(2024, 언어치료연구 33(4))은 같은 대상자라도 스스로 이야기하기와 청각적
단서를 듣고 다시 말하기에서 산출이 유의하게 달랐다. 중증일수록 단서 효과가 줄었다(CIU 수에서만
상호작용). 이 논문은 휴지를 측정하지 않았으므로 300ms/2000ms 문턱의 근거로는 쓰지 않는다.
문턱 근거는 한국어 노인 발화의 휴지 문헌에서 따로 찾는다.

## 4. 되묻기 탐지의 재현율 미측정

`repeat-ko-v2`에서 오탐 하나를 고쳤다. `clarify.huh-eo`가 `어` 부분 일치로 "어지럽습니다"를
되묻기로 잡던 문제였고, standalone 규칙이 발화 전체를 덮을 때만 인정하도록 바꿨다.

하지만 **재현율은 한 번도 측정된 적이 없다.** 손으로 쓴 정규식이 실제 노인 발화의 되묻기를
얼마나 놓치는지 모른다. 라벨 세트를 만들어 precision/recall을 측정하고, 규칙 확장 또는 LLM
보조 분류를 검토한다.

## 5. `F0_VARIATION`의 유성음 게이트

실기기 통화에서 `INSUFFICIENT_VOICED_AUDIO`로 측정 실패했다. 조건은 다음과 같다.

```python
mask = voiced & isfinite(f0) & (probability >= 0.8)
if valid.size * 256 / sample_rate < 2:   # 유성음 2초 미만
```

`probability >= 0.8`과 `2초`가 모두 코드에 박힌 임의값이다. pYIN에서 0.5~0.6이 흔히 쓰이는
값이라 0.8은 보수적일 수 있다. 16초 발화에서 유성음 2초를 못 채우는 것이 정상인지 먼저
확인해야 한다. 두 값을 `Settings`로 올리고 실제 유성음 길이 분포를 측정한다.

## 6. 품질 게이트의 표본이 부족하다

2026-08-13에 `quality_min_active_dbfs`를 -45 → -55 dBFS로, `quality_active_percentile`을
75 → 90으로 조정했다. 근거는 실기기 실측이다.

```
peak  -30.4 dBFS
rms   -49.8 dBFS
p75   -48.0 dBFS
p90   -45.7 dBFS   ← 기존 임계값 -45.0에 0.7 dB 차이로 탈락
```

발화 프레임 레벨이 -46 dBFS 부근이라 10 dB 여유를 두고 -55로 정했다. 진짜 무음이나 마이크
차단은 -70 dBFS 이하로 떨어지므로 여전히 걸러진다.

다만 **표본은 iPhone 15 Pro 한 대, 통화 3건이다.** 기기·거리·환경이 다르면 분포가 달라진다.
`scripts/acoustic_quality_report.py`로 실패 사유 분포를 계속 관찰하고, 다른 기기가 붙으면
다시 확인한다.

## 7. `parent_min_speech_seconds = 20`의 근거

통계적 안정성 근거 없이 정해진 값이다. 발화 길이별로 지표의 분산이 어떻게 변하는지 측정해
결정해야 한다. 현재 개발 환경에서는 반복 검증을 위해 8초로 낮춰 두었다.

## 8. 녹음 시작 지연 의심 (확인 필요)

2026-08-13 통화에서 대본의 첫 문장이 전사에 나타나지 않았다. 분석용 PCM writer는
`마이크 publish 완료` 이후에 부착되므로, 통화를 받자마자 말하면 앞부분이 유실될 수 있다.

의도한 대본과 실제 전사를 비교하는 방식으로 재현 여부를 먼저 확인한다. 재현되면 writer
부착 시점을 앞당기거나, publish 이전 구간을 버퍼링하는 방법을 검토한다. 통화 앞부분이
항상 유실된다면 기침을 포함한 모든 지표에 영향을 준다.
